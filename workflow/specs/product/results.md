# Test results

Planning area `RES`; RES-1 implements tester availability and RES-2 implements private draft saving and immutable submission. See the [product spec](../PRODUCT-SPEC.md), [tester routes](../TECHNICAL-SPEC.md#tester-routes) and [access controls](../SECURITY-SPEC.md#sign-in-and-access-control).

## RES-1 See the tests available to me

A Beta Tester can read the Open and Closed rounds in their own workspace and the instructions needed to test each case against its current build. Closed rounds remain available as read-only reference. Availability is shared by both testers in a workspace; there is no assignment or completion filtering. Draft rounds are unavailable. This requirement does not record outcomes, submissions, observations or history, and does not provide AI feedback.

Each criterion is labelled happy, boundary, failure, adversarial or ambiguous.

- **RES-1.1** (happy) "Tester home" retains the account information and sign-out control of [ACC-1](accounts.md#acc-1-sign-in-and-out-by-role) and shows an "Available tests" section. It lists every Open and Closed round in the signed-in tester's workspace once, by creation time newest first and descending ID when times tie. Each entry is the round title linking to its tester detail page, followed by its state as "(Open)" or "(Closed)". Draft and other workspaces' rounds are absent, including their titles and identifiers. Both testers in a workspace see the same available rounds.
- **RES-1.2** (boundary) With no available rounds, including a workspace containing only Draft rounds, the section says "No tests available." and offers no round links. A workspace containing only Closed rounds lists those rounds as reference.
- **RES-1.3** (happy) Following an available round opens a page with the round title as its page title and heading, "State: Open" or "State: Closed" matching the round's actual state, a "Test cases" section and a "Tester home" link. Each case appears in ascending ID order with its title and the headings "Steps", "Expected result", "Linked acceptance criteria" and "Current build", followed by the corresponding text. Linked criteria appear in ascending ID order and include only that case's links. The current build follows the existing [round definition](rounds.md#round-states): a retest changes the label shown only for cases that build covers, including repeated or overlapping retests; unselected cases keep their previous current build. Reloading after a committed retest shows the new labels, which remain visible after closure. Published-round invariants come from RND-3; this page does not repair missing data or show build history.
- **RES-1.4** (adversarial) On both tester pages, signed-out visitors redirect to sign-in without a redirect target, and Test Coordinators get the fixed 403 of [ACC-1.4](accounts.md#acc-1-sign-in-and-out-by-role), before any round lookup. All workspace record lookups use the shared helper of [ACC-2.4](accounts.md#acc-2-create-an-isolated-demo-workspace). A detail URL naming a Draft, missing or foreign-workspace round gives the same status 404 and fixed "Page not found." page, without its title, state, cases, criteria or build labels. Foreign rounds are unavailable in every state, including Closed.
- **RES-1.5** (adversarial) Both pages accept GET only for Open and Closed rounds; other methods, including HEAD, get 405, except that Django's CSRF middleware first gives 403 to unsafe requests without a valid token or with a foreign Origin, as in [the round action rules](rounds.md#rules-for-every-round-action). Reading or refusing either page changes no round, case, criterion, link or build and creates no tester result. The detail page offers no edit, publish, retest or close controls. In Open rounds, each case has a "Record result" link to its current-build entry page under RES-2; Closed rounds have no result-entry links. The detail page itself has no result form. Existing sign-out remains available on the home page.
- **RES-1.6** (failure) Successful pages, signed-out redirects, 405 responses and storage-failure responses are never cached (`Cache-Control: private, no-store`). A database failure while loading the session or user, reading available rounds or loading detail content returns the fixed 503 page of [ACC-2.5](accounts.md#acc-2-create-an-isolated-demo-workspace), with no partial round content or changes. Session-save failures after the view retain the existing [session persistence behaviour](../TECHNICAL-SPEC.md#data-model).
- **RES-1.7** (adversarial) Round and case titles, steps, expected results, linked criterion text and current-build labels on tester pages follow the existing [escaped plain-text and direction-isolation rules](rounds.md#rules-for-every-round-action), including line breaks and page-title isolation. Markup, attribute-breaking text and stored direction controls cannot execute or escape their text boundary. A round title used as a home-page link follows the same rules. These checks cover coordinator-written text crossing into another user's tester page, including text stored outside the forms.
- **RES-1.8** (boundary) After a coordinator's close has committed, the next home-page GET retains that round with "(Closed)" and the next detail GET remains available with "State: Closed" and the same case instructions and current-build labels. An already displayed page remains until navigation or reload; there is no polling or live update, and a request whose state lookup preceded the close may finish showing Open. Publication makes a round appear on the next home GET with "(Open)".

## RES-2 Save and submit an outcome with observations

A Beta Tester records their own result for a case's current build while its round is Open. One private row per tester, case and build holds a replaceable draft or an immutable submission. Earlier rows remain tied to their original build and the case's frozen criteria; this requirement adds no history, coordinator review or AI screen.

- **RES-2.1** (happy) "Record result" opens a page titled and headed "Record result", showing "Test case" and "Current build" with the case title and build label, and a "Back to round" link. With no result, "Outcome" has an empty choice followed by "Pass" and "Fail", "Observation" is empty, and "Save draft" and "Submit" buttons are available. Either button requires a valid outcome; Save draft persists the fields and redirects to the same page with "Status: Draft" and the saved values. Submit can create a submission directly or submit a draft, persists the supplied values, and redirects to the same page with "Status: Submitted", "Outcome" and "Observation" shown as read-only text, with no form or action buttons. An empty submitted observation says "No observation." Reload and a new signed-in session recover the saved state; GET never creates a row. No success flash message is required.
- **RES-2.2** (boundary) Save draft and Submit use identical validation. An absent or invalid outcome gets "Choose Pass or Fail." Observation uses the trimming, line-break normalization, null-character and hidden-direction checks of the [round text rules](rounds.md#rules-for-every-round-action). At most 2000 characters are accepted after normalization and trimming; 2001 gets "Enter at most 2000 characters." An empty observation is accepted for Pass; Fail requires a visible character and otherwise gets "Enter an observation for Fail." A nonempty invisible-only Pass observation gets "Enter an observation with a visible character." Invalid input shows the same form with status 200, the supplied values and field errors, without changing a row. An absent or unknown button action gives the non-field error "Choose Save draft or Submit." and no write.
- **RES-2.3** (adversarial) Signed-out requests redirect to sign-in without a redirect target; coordinators get the fixed ACC-1.4 403, before domain lookups. Workspace lookups use ACC-2.4's helper. A missing, Draft or foreign-workspace round, a case outside the authorized round, or a missing build or build outside that round's coverage of the case gets the same fixed ACC-2.4 404, before any state conflict. The tester identity comes exclusively from the signed-in account. Each tester sees and changes only their own row, including when two testers share a workspace; submitted tester/result identifiers cannot select another row. No coordinator result route is added.
- **RES-2.4** (boundary) Entry GET and POST require an Open round and the named build to be the case's current build. Closed entry requests get status 409 and "This action is not available while the round is Closed." A formerly current covered build gets status 409 and "This build is no longer current. Reload the round to record a result." Neither refusal changes earlier rows or copies them to another build. A retest gives each selected case a fresh empty entry for the new build; unselected cases retain their entry. Closing keeps all rows and the existing read-only round detail, which has no result-entry links.
- **RES-2.5** (adversarial) Every POST after a row is submitted gets status 409 and "This result has already been submitted.", even if values are identical or invalid. A submitted current-build row remains readable on its entry page while Open. Writes serialize with close, retest and other result writes: after acquiring the round lock, re-check authorized round/case/build membership, Open state, current build and submission status before validating and writing. Two draft saves leave the last serialized values; two submissions create one submitted row and the later request gets 409. A save following submission gets 409. A close or selected-case retest that commits first causes the result write to get 409; a result write that commits first remains tied to its original build and unchanged by the later action. Refusals change nothing.
- **RES-2.6** (failure) Entry responses returned by the view, including redirects, invalid forms, 405, 409 and storage failures, have `Cache-Control: private, no-store`. Database failures during lazy authentication, reads, rendering or persistence return the fixed ACC-2.5 503 with no partial result write or content. Existing session-save behaviour after the view remains as specified in the [data model](../TECHNICAL-SPEC.md#data-model). Refused actions never alter rounds, cases, criteria, links, builds or results.
- **RES-2.7** (adversarial) Entry accepts GET and POST only; other methods, including HEAD, get 405. Django's CSRF middleware first gives the fixed 403 to unsafe requests lacking a valid token or carrying a foreign Origin; no data changes. GET is read-only; only the two recognized POST actions can persist a result.
- **RES-2.8** (adversarial) Case titles, build labels and observations, including refused form values and text stored outside forms, follow the existing escaped plain-text and direction-isolation rendering rules. Submitted observations preserve line breaks; form inputs use `dir="auto"`. Markup, attribute-breaking input, direction controls and zero-width characters cannot escape their text boundary or execute. These checks include coordinator-written case/build text crossing into the tester's entry page and the tester's own observation.

## RES-3 Review my earlier results

A Beta Tester reads their own saved drafts and submissions for one Open or Closed round, including both current and earlier builds. This read-only history preserves the original case, frozen linked criteria and build; it adds no result editing, coordinator review, AI, filters or pagination.

- **RES-3.1** (happy) Every available Open or Closed tester round detail page has one "My results" link. It opens a page titled and headed "My results", showing the round title under "Round", its actual "State: Open" or "State: Closed", and a "Back to round" link to that tester detail page. The page is available even when the tester has no results.
- **RES-3.2** (happy) The page lists every saved result belonging to the signed-in tester for that round once, including drafts and submissions for current and earlier builds, ordered by original build ID descending, then case ID ascending. Each result shows "Test case" with its original case title, "Linked acceptance criteria" with only that case's frozen linked criteria in ascending criterion ID order, "Build" with its original build label, "Outcome" as "Pass" or "Fail", "Observation" with its saved text or "No observation." when empty, and "Status: Draft" or "Status: Submitted". A submission additionally shows "Submitted at" with its stored timestamp formatted `YYYY-MM-DD HH:MM:SS UTC`; drafts show no submission time. Builds without a saved result produce no entry, and an empty list says "No results yet.".
- **RES-3.3** (boundary) A committed draft save or submission appears on the next history GET; replacing a draft shows its latest saved values rather than a revision list. After a selected-case retest or closure commits, the next GET retains every earlier row with its original build and frozen case/criteria, including drafts. Retesting neither copies a result to the new build nor hides a current-build result. The displayed page stays unchanged until navigation or reload; there is no polling or snapshot guarantee across concurrent changes.
- **RES-3.4** (adversarial) Signed-out visitors redirect to sign-in without a redirect target; Test Coordinators get the fixed ACC-1.4 403 before round lookup. Round lookup uses ACC-2.4's workspace helper and excludes Draft: missing, Draft and foreign-workspace rounds in every state get the same fixed 404 page without round or result content. Result ownership comes only from the authenticated tester, and displayed rows must have a case and covering build in that authorized round. Same-workspace testers cannot read each other's rows; query parameters naming a tester, result, case or build do not select or filter rows. No coordinator history route is added.
- **RES-3.5** (adversarial) History accepts GET only; other methods, including HEAD, get 405, except that Django's CSRF middleware first returns the fixed 403 for unsafe requests without a valid token or with a foreign Origin. Reading or refusing history changes no domain records. The page has no forms or result-entry, edit, submit, retest or close controls.
- **RES-3.6** (failure) Successful history pages, signed-out redirects, 405 responses and storage-failure responses have `Cache-Control: private, no-store`. Database failures during lazy authentication, round/result/related-content reads or rendering return the fixed ACC-2.5 503 page without partial history content or domain changes. Session-save failures after the view retain the existing [session persistence behaviour](../TECHNICAL-SPEC.md#data-model); no observations or request fields are logged.
- **RES-3.7** (adversarial) Round and case titles, linked criterion text, original build labels and observations follow the existing [escaped plain-text and direction-isolation rules](rounds.md#rules-for-every-round-action), preserving line breaks. Markup, attribute-breaking text, stored direction controls and zero-width characters cannot execute or escape their text boundary. Checks include coordinator-written context crossing into the tester's page and observations stored outside forms.
