# create-pull-request

Creates or updates a draft pull request and follows its configured checks through completion within the human's delivery authorization.

**Input:** Slice branch or local candidate, optional issue, plan, agent handoffs and actual checks.

1. Inspect the candidate against the intended base and preserve unrelated edits. Apply [AGENTS.md's Git authorization and commit rules](../../AGENTS.md#git): a normal human slice request includes draft-PR delivery; explicit restrictions override it. Review text may be prepared early, but this is not a reason to leave authorized commits/pushes undone. If the base changes, integrate only as authorized, check affected behaviour and run the [slice tier's required checks](slice.md) on the final integrated candidate. Refresh review after conflict resolutions or other substantive changes; reclassify if a Fast lane change affects behaviour, acceptance criteria or security controls.
2. For Standard/High, check that verifier and any required security-reviewer covered the final candidate (commit range or dirty-tree manifest), apart from summary-only changes. For Fast lane, require targeted check evidence and human diff review; verifier coverage and full verification are not required. A draft may open earlier to run CI, with outstanding review/checks clearly marked pending. If evidence is stale, follow the slice skill's freeze, verify and repair steps. Never call an incomplete draft ready to merge.
3. Fill in `.github/pull_request_template.md` for a reviewer who has not seen the conversation. Lead with the problem and final behaviour; keep criterion-to-check results, tier, review outcome and material limitations concise. Link the plan/log for exact review candidates, specialist ranges, resource usage and process history instead of repeating them. Omit token counts, telemetry caveats, resolved corrections and abandoned approaches unless they explain a tradeoff in the final change. Include actual check results even without GitHub CI; report unresolved findings and leave human checkboxes unticked.
4. Within authorization, push the incremental commits and create/update the draft PR. Do not ask again for actions already authorized by the human's slice request. If a connector cannot perform the action, use an available authenticated CLI where permitted; report a concrete access blocker only when it remains unresolved. With an explicit local-only/no-push/no-PR restriction, perform the remaining permitted work and report the restriction and outstanding delivery steps.
5. Read the current PR head and inspect its configured required CI results. Wait for completion; fix failures within scope and the [slice repair limit](slice.md), push the repair and check the new head. After any final summary/log commit, verify that latest head too. Report failed, cancelled, missing or unavailable checks honestly; never substitute an older green run. Only run configured, separately authorized preview/deployment checks; do not create services or infer production-release permission. Leave human checkboxes unticked and never merge/release without explicit authorization.

**Done when:** The authorized draft PR URL, latest head and successful configured required CI are reported with review limits, or a specific human delivery restriction/external blocker and remaining action are stated. Prepared text or local passing checks alone do not finish an authorized draft-PR delivery.
