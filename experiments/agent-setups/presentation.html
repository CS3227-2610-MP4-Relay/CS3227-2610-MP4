The answer first

Five findings

  1. Quality did not separate the setups. Every comparison run on both tasks passed its hidden acceptance suite and full verification, its own tests caught every planted bug, and no blind review found a High issue. Across all 71 runs, 70/71 caught every planted bug.
  2. Hand-offs are the cost. In MP4, about 54% (task 1) and 55% (task 2) of an average run's money went on subagents re-reading the repository. Setups that build in one session cost 45–63% less than MP4 and took 40–65% of its time.
  3. The add-ons do not pay. caveman, ponytail and headroom cost 32–49% less than MP4 on task 1, but −19% to +10% on task 2. What moved was how many subagents the coordinator started, not the add-on.
  4. Methodologies are one session with ceremony. superpowers and spec-kit matched a single session's cost and quality. They bring planning and test-first habits, but no independent review unless asked.
  5. The ideal: build in one session, keep one independent reviewer. The portable version cost about half of MP4 on Opus and far less on Sonnet, with the same quality. A guarded profile keeps weaker models on track; on Haiku it is not reliably cheaper than MP4, but it is up to twice as fast.

Task 1 · #68: refuse hidden text-direction characters

  • Small: one validation rule across 12 round-text inputs.
  • Hidden suite: 132 tests (108 refusals, 24 allowed).
  • Planted bugs: no check; two controls allowed; a mark refused; build labels unchecked.
  • 21 comparison runs: 2 per setup, 3 for MP4.

Task 2 · #16: request a retest (RND-5)

  • Larger: a new page, form and service, checks under a row lock, a build cap, label rules and escaping.
  • Hidden suite: 27 HTTP tests.
  • Planted bugs: foreign cases accepted; cap off by one; labels compared as typed; any round state accepted; label unescaped.
  • 16 runs: 1 per setup, 2 for MP4 and v5.

Held fixed

  • The same prompt and the human's decisions, given up front.
  • Claude Code 2.1.312, pinned and headless; web, GitHub, push and installs blocked.
  • Each run in its own clone with no later history, and its own test database.
  • Add-ons loaded per session only, pinned to a commit.
  • The method was written down before the first counted run of each task.

Why it happens

How a hand-off costs money

MP4: a coordinator and fresh subagents

CoordinatorBuilder · checkpoint 1Builder · checkpoint 2VerifierSecurity reviewerBuilder · repairVerifier · recheck

Every subagent starts with an empty context. It reads AGENTS.md, its role, the specs and the code again, and caches all of it afresh. The coordinator then reads each report back. A median MP4 run started 9 of them on task 1 and 10 on task 2.

One session: build once, review once

Session: spec → tests → code → docs → checksOne reviewer

The session keeps its context and its cache for the whole build, so the repository is read once. One independent reviewer still reads it cold, because that independence is what catches what the builder cannot see in its own work.

Results

The add-ons, one at a time

caveman: terse output

  • Promise: fewer output tokens.
  • Output tokens: task 1: 107k vs MP4 160k · task 2: 200k vs MP4 223k.
  • Cost: task 1: $6.13 vs MP4 $8.97 · task 2: $10.85 vs MP4 $11.46.
  • Verdict: real but small. Output is about a fifth of cost, and reports came out in normal prose anyway.

ponytail: smallest change

  • Promise: smaller diffs.
  • Test lines: task 1: 126 vs MP4 240 · task 2: 934 vs MP4 1128.
  • Cost: task 1: $4.54 vs MP4 $8.97 · task 2: $9.32 vs MP4 $11.46.
  • Verdict: smaller tests on task 1, same quality; no saving that survived task 2.

headroom: compressing proxy

  • Promise: compress the context sent to the model.
  • Compressed: 0.9–1.1% of request traffic.
  • Cost: task 1: $5.85 vs MP4 $8.97 · task 2: $12.55 vs MP4 $11.46.
  • Verdict: too little compression to matter, and it routes your credentials through a third-party proxy.

Subagent runs per add-on run: 6 on task 1 against MP4's 8–10; 9–12 on task 2 against 9–12. Cost followed the subagent count, not the add-on. None of the three changed quality.

Results

Workflows, models and methodologies

MP3 six roles

task 1: $5.77, 22 min · task 2: $11.88, 37 min. The most roles and the most test code, with no quality gain. It ran cheaper than MP4 only because each of its roles reads less.

Solo session

task 1: $3.35, 13 min. One session plays every MP4 role: the cheapest Opus setup on task 1. Its weakness is that it reviews its own work.

Sonnet

All-Sonnet MP4: task 1: $2.25, 14 min. A Sonnet builder under Opus: task 1: $5.72, 22 min. Sonnet was enough for both tasks; the saving comes from running every session on it.

superpowers and spec-kit

superpowers: task 1: $4.14, 12 min · task 2: $5.60, 17 min. spec-kit: task 1: $4.40, 12 min · task 2: $5.48, 23 min. Both build in one session, so both cost about what a single session costs. Neither adds an independent review unless asked.

The ideal setup

The ideal setup: how it works

1

Specify
requirements first, short plan

2

Build
tests fail first; every listed value tested

3

Check
every mention, every old test, every decision

4

Freeze
full verification on the final commit

5

Review
one independent read-only reviewer

6

Repair
at most two rounds, then ask

Two switches

AGENT_PROFILE strong for Opus, Sonnet and GPT-5-class models; anything else, or unset, gets guarded: a ticked checklist, hard stops, tests shown failing first, a can-the-tests-fail check, and numbers only from commands run.

AGENT_REVIEW_MODEL optionally a stronger reviewer. Otherwise the reviewer uses the session's model; the model never picks one.

One file per project

agent-workflow/project.md holds what differs between repositories: the verification command, folders, where requirements, docs, plans and accepted risks live, the high-risk areas and the size budget. The workflow itself never names a project.

Any tool that reads AGENTS.md

The installer adds a marked block to AGENTS.md, the workflow folder, and adapters: Claude Code subagents and a skill, Codex agents, and a skill that Codex and Hermes read. Hermes delegates the review as a task.

What each step fixed

  • v2 removed the Medium spec findings on Sonnet and Opus.
  • v3 stopped Haiku choosing Opus reviewers, and Hermes sampling values.
  • v4 made every unset DeepSeek run choose guarded.
  • v5 let Haiku record accepted risks in the right home, and installs into any repository.

v6: three rules from v5's own reviews

  • v5 on task 2 had one Medium finding each on Sonnet ($2.29) and Haiku ($2.18): an invented approval and a mocked service.
  • v6 on the same task had none, on Sonnet ($2.20) and Haiku ($1.85), with every planted bug caught.
  • One run each: the rules cost nothing, but whether they reliably help needs more runs.

Conclusion

Takeaways

If you run coding agents on a real repository

  1. Build in one session. Hand-offs to builder subagents doubled cost and time here with no quality gain.
  2. Keep exactly one independent reviewer. It is the part a session cannot do for itself, and it is cheap.
  3. Try the cheaper model first. Sonnet passed every check on both tasks at a fraction of Opus's cost.
  4. Give weaker models a checklist, not freedom. Hard stops, tests shown failing first, numbers only from commands run.
  5. Before review, check consistency. Every mention, every old test, every decision: that is where the findings were.
  6. Write the project's facts down once. Commands, homes and budgets in one file let the same workflow move between repositories and tools.

Skip, or measure first

  • Output-compression and proxy add-ons: small or no savings, and a proxy sees your credentials.
  • More roles: MP3's six roles cost more and found nothing extra.
  • Letting the model pick its reviewer or profile: it chose the expensive or the loose option.
  • Trusting one task: task 1 made the add-ons look useful; task 2 did not.

Conclusion

Limits

  • Two tasks in one Django project, both with the human's decisions given up front. Large or ambiguous work, where review has more to find, may rank the setups differently.
  • One to three runs per setup and task. Only large, consistent differences are worth reading.
  • Quality hit the ceiling on both tasks, so the comparison mostly measures cost and time.
  • Opus wrote the hidden suites and the blind reviews, and built most candidates. The hidden suites and planted bugs are the objective checks.
  • Costs are list prices from each tool's report; the subscription bills differently. Runs overlapped, so times include contention.
