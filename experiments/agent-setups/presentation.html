Design

The ideal setup

1

Specify
spec first, short plan

2

Build
tests fail first, smallest change

3

Check
every mention, every old test

4

Freeze
full verification, commit

5

Review
one independent read-only reviewer

6

Repair
at most two rounds

Why this shape

  • Building in one session removes the hand-offs that drive cost.
  • An independent reviewer is the one thing a session can't give itself; the earlier DeepSeek run showed self-review misses scope and governance.
  • Subagents inherit the session's model, so a cheap session stays cheap.
  • No add-on: none improved quality, and headroom proxies your credentials.

One switch: RELAY_PROFILE

strong Opus, Sonnet, GPT-5-class: the lean slice as written.

guarded Haiku, DeepSeek or unsure: a ticked checklist, hard stops before scope or rule changes, tests shown to fail first, a can-fail self-check and numbers only from commands run.

Unset: the model picks by its own identity, and defaults to guarded.

Conclusion

Takeaways

Do

  • Build in one session; keep exactly one independent reviewer.
  • Run that session on the cheapest model that passes: Sonnet here.
  • Give weaker models the guarded profile: checklist, hard stops, evidence.
  • Check every mention and every old test before freezing.

Mind

  • One Standard-tier task with decisions given up front.
  • 2–3 runs per setup: only non-overlapping ranges count.
  • Opus wrote the hidden tests and the blind reviews.
  • Costs are list prices from each tool's own report.
